## Session 21 (2026‑10‑27): version 1.0 — Find in Finder, plugins, packaging and CI

- **Find in Finder** (Phase 4): port of upstream `FindInFinderDlg` (IDD_FINDINFINDER_DLG as an RcDialog, translated
  as `<FindInFinder>`), WM_FINDALL_INCURRENTFINDER, `createFinder` / `findInFinderFiles`: the search runs inside the
  results of a Finder into a new, closable results panel docked with the main one. Test: `tst_findreplace findInFinder`.
- **Plugin API** (Phase 9, [docs/PLUGINS.md](docs/PLUGINS.md)):
  - `src/plugins/PluginInterface.h`: the upstream plugin ABI (`setInfo`, `getName`, `getFuncsArray`, `beNotified`,
    `messageProc`, `isUnicode`) with C linkage; `NppData` holds opaque handles plus `_nppSend` / `_sciSend`, so the
    `NPPM_*` keep their numbers. Strings are UTF‑8; `NPPM_*_UTF8` variants where upstream passes `wchar_t*`;
    `getAbiVersion` guards against incompatible builds. `PluginDockingQt.h` docks a plugin's `QWidget*`
    (NPPM_DMMREGASDCKDLG).
  - `PluginsManager` on dlopen / dlsym: `<root>/<Name>/<Name>.so` from `~/.local/share/notepadlx/plugins`,
    `NPLX_PLUGIN_PATH`, `<exe>/../lib/notepadlx/plugins` and the install prefix. The Plugins menu, plugin commands
    in the Shortcut Mapper and `shortcuts.xml`, NPPM_ALLOCATECMDID / MARKER / INDICATOR, toolbar icons.
  - ~110 NPPM_* messages of NppBigSwitch; NPPN_* notifications (READY, FILEOPENED, FILESAVED, BUFFERACTIVATED,
    LANGCHANGED, DOCORDERCHANGED, GLOBALMODIFIED, FILEBEFORERENAME / FILERENAMED, DARKMODECHANGED, SHUTDOWN…) and
    the Scintilla notifications, the macro relay.
  - Plugins › Open Plugins Folder…, Settings › Import › Import plugin(s)…, Debug Info lists the plugins, `-noPlugin`.
  - Samples: Hello World (menu, shortcut, toolbar icon, editing) and Docking Sample (a Qt panel). `tst_plugins`.
  - Not ported: lexer plugins (`NPLX_TODO(Phase 9+)`), Plugins Admin (no Linux plugin list yet).
- **Packaging** (Phase 10): the release packages are the AppImage and the `.deb` only (Flatpak and `.rpm` were tried
  and dropped to keep the release simple). File associations: the `.desktop` `MimeType=` is generated by
  `tools/gen_mimetypes.py` from the `langs.model.xml` extensions through shared-mime-info (text types only).
- **CI** (`.github/workflows/ci.yml`): build + tests on Ubuntu 26.04 and the desktop / AppStream validation.
- 19/19 suites pass.

## Session 13 (2026‑10‑25): version 0.5 — the editor keys

- **Keys:** the Scintilla keys Ctrl+<letter> did nothing on a real keyboard (Ctrl+D Duplicate Line, Ctrl+L,
  Ctrl+Shift+L, Ctrl+A, Ctrl+C/X/V, Ctrl+Z/Y). A real key press carries its control character as text (Ctrl+D =
  "\x04", on Wayland and X11), and the port of upstream's WM_CHAR filter (`_npcNoInputC0`) swallowed the whole key
  event; on Windows WM_KEYDOWN runs the command and only WM_CHAR is dropped. Now only the character is dropped and
  the key still goes to Scintilla (`ScintillaEditView::keyPressEvent`). QTest::keyClick sends "d" as the text, so
  the tests did not see it: `tst_shortcuts commonEditingKeys` now sends the text of a real key press. Found with
  `QT_LOGGING_RULES=qt.gui.shortcutmap=true` on the user's GNOME Wayland session.

## Session 12 (2026‑10‑25): version 0.4 — the caret at the start of a line

- **Caret:** at the start of a line the caret did not blink. Scintilla's Qt `Window::GetClientPosition` returned the
  viewport's geometry in the scroll area, which is 1,1 when the editor has a frame (`borderEdge`): the text area
  began 1 pixel right of the margins and the first pixel column of text was never painted, so the caret drawn
  there stayed on the screen. The client area now starts at 0,0, as Win32 `GetClientRect` (`// NPLX:` in
  `third_party/scintilla/qt/ScintillaEditBase/PlatQt.cpp`). Test: `tst_look caretBlinksAtLineStart`.
- **Keys:** a report that the shortcuts do not work: found and fixed in 0.5 (session 13).
